# Stage 9 - OOP 与工程质量审查（基于现有真实源码）

## 已确认的设计

- `App extends PApplet`：承载配置读取、事件处理、游戏循环、回合、HUD、地形、伤害及结果界面。
- `App.Tanks`：非静态内部类，存放生命、燃油、角度、分数、护盾状态；实现移动/瞄准/射击。
- `App.Projectiles`：非静态内部类，记录所属坦克、精确坐标、速度、风速和爆炸状态。
- `App.DeathExplosion`：非静态内部类，记录坦克死亡爆炸的受害者/责任方、半径和动画帧。
- `App.Tree`：非静态内部类，保存树木位置。

## 优点

- 已使用 `PApplet` 继承及不同实体的专用类。
- 具备跨关卡计分、归属正确的伤害、地形塌陷、投射物和扩展道具等核心规则。
- 147项JUnit覆盖逻辑与headless渲染方法；最新用户上传的覆盖率平均93.20%。

## 仍需如实说明的限制

1. `App.java` 接近千行，是明显的高耦合协调类，不符合严格的单一职责原则。
2. 多个共享集合是 `public static` 可变状态，测试之间存在潜在共享污染风险。
3. 内部实体类依赖外部 `App` 的字段，尚未通过依赖注入实现解耦。
4. 原始A2要求的 Java 8 **运行**兼容性尚未通过真实JDK8 `gradle run` 验证，只有源代码目标与后续构建字节码检查。
5. headless 测试不直接比较Processing游戏窗口的像素。

## 后续结构重构建议（本包未执行）

`GameState`（关卡/回合/分数）、`Terrain`（地形平滑和爆炸变形）、`PhysicsEngine`（炮弹、风、重力）、`Tank`、`Projectile`、`Renderer`（Processing绘制）、`PowerUp`（可购买道具接口）。改动范围大，应使用既有147项回归测试逐模块迁移，不能直接把当前设计描述成已实现上述拆分。
